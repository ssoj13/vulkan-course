Our first program creates one object, a `VkInstance`. To understand what that object is, we first need the piece of
software it connects us to: the **loader**.

## Where this fits

We move down from the application into the **loader & driver** layer, and create the first object of the **Vulkan
API** layer. [Lesson 2](lesson:talking-to-gpu) spoke of "the driver" as one piece; here it splits into a loader, layers
and one driver per vendor. The chain:

`your program → loader → layers → driver (ICD) → GPU`, and on the API side `VkInstance` as the root of the object tree.

The loader is built on the drivers and layers it finds on the machine; the instance is built on the loader: it is your
program's registered connection to it, with the layers and extensions you chose. Everything that follows hangs off
it: the [validation layer](lesson:validation) is enabled on it, and the GPUs are found through it.

## The loader: a switchboard

Your program never talks to the GPU driver directly. It talks to the **Vulkan loader** (`vulkan-1.dll`), a small
library from Khronos that ships with every driver. At startup the loader:

1. finds the installed **drivers** (one per GPU vendor - a machine can have NVIDIA and Intel at once),
2. finds the installed **layers** - libraries that can sit between your program and the driver,
3. routes each of your calls through the enabled layers to the right driver.

```
your program -> loader -> [layer] -> [layer] -> driver (ICD) -> GPU
```

## Layers: implicit and explicit

A **layer** sees every call that passes through it. Validation, capture tools (RenderDoc), overlays (Steam, screen
recorders) and profilers are all layers. There are two kinds:

- **Explicit layers** are loaded only when the application (or `vkconfig`) asks for them by name. The validation layer
  is explicit.
- **Implicit layers** are loaded into *every* Vulkan program automatically, because some installed software registered
  them.

<Aside type="caution" title="A real example from the machine this course was built on">
On Windows the loader finds layers through the registry: `SOFTWARE\Khronos\Vulkan\ImplicitLayers` and
`...\ExplicitLayers` under both `HKEY_LOCAL_MACHINE` and `HKEY_CURRENT_USER`, plus keys the GPU driver writes under its
display-adapter entry. On the development machine there were **eight** implicit layers: six registered by installed
software (RenderDoc, Bandicam, the Epic Games overlay, the Steam overlay, Steam's Fossilize, Nsight Systems) and two by
the NVIDIA driver itself (`VK_LAYER_NV_optimus`, `VK_LAYER_NV_present`). All of them load into every Vulkan program on
that PC, including ours - and Bandicam's layer even prints a warning that its API version is older than ours. That
warning is not about our code. Each implicit layer's JSON manifest names an environment variable that disables it
(for example `DISABLE_LAYER_NV_OPTIMUS_1`), should a layer ever get in your way.
</Aside>

## The instance

A **`VkInstance`** is your program's connection to the loader: "I am this application, I use Vulkan 1.4, and I want
these layers and these extensions." It is the root of the object tree; everything else is created from it, directly
or indirectly.

This whole struct is optional metadata; the one field with a real effect is `apiVersion`: the **highest** Vulkan

fixes.

### 3. See what is available

<Step file="01_instance" region="list-extensions" />

An **extension** is optional API functionality with a name such as `VK_KHR_surface`. *Instance* extensions extend the
loader and instance (window surfaces, debug messages); *device* extensions, which we meet in lesson 10, extend what a
GPU can do. An extension must be **enabled at creation time**; listing it only tells you it exists.

## Underneath

- The loader is open source ([KhronosGroup/Vulkan-Loader](https://github.com/KhronosGroup/Vulkan-Loader)). On Windows,
  current drivers register their driver JSON manifest through the display adapter's own registry keys; the older
  `HKEY_LOCAL_MACHINE\SOFTWARE\Khronos\Vulkan\Drivers` key is still read too (on the development machine it did not
  exist at all).
- Every instance-level call goes through the loader's **trampoline** code, then through each enabled layer, and
  finally into the loader's **terminator**, which forwards it to every driver. Layers are chained: each one calls the
  next.
- `vkCreateInstance` itself does not touch the GPU. It only sets up the loader, the layers and each driver's instance
  state.
