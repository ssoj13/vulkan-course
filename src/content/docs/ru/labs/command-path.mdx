CPU и GPU — два процессора, которые работают одновременно. Интерактив отвечает на один вопрос: **когда GPU на самом
деле выполняет работу, которую попросил CPU, и чем CPU занят в это время?** Путь команды разобран в уроке
[Как программа разговаривает с GPU](lesson:talking-to-gpu#путь-одного-draw-call).

На трёх дорожках идут три кадра цикла рендера. На дорожке **CPU** каждый кадр сначала делает работу приложения,
потом записывает command buffer (`vkBeginCommandBuffer`, вызовы `vkCmd*`, `vkEndCommandBuffer`) и вызывает
`vkQueueSubmit2`. Этот вызов возвращается почти сразу: пакет теперь лежит в **очереди**. Чуть позже командный
процессор GPU забирает его, и дорожка **GPU** его исполняет. Закончив, GPU сигналит **fence** кадра; по fence CPU и
может узнать об этом через `vkWaitForFences`.

Переключатель над таймлайном — тот самый выбор, который делает любой настоящий рендерер. Ждать fence сразу после
отправки (1 кадр в полёте) просто, но тогда CPU простаивает, пока работает GPU, а GPU простаивает, пока CPU готовит
следующий кадр. Если ждать только перед повторным использованием command buffer (2 кадра в полёте, два command
buffer, два fence), CPU записывает кадр N+1, пока GPU исполняет кадр N. Совсем убрать ожидание нельзя: запись в
command buffer, который GPU ещё не доисполнил, нарушает правило «`commandBuffer` must not be in the recording or
pending state» (`VUID-vkBeginCommandBuffer-commandBuffer-00049`).

Длительности условные, в тиках, а не замеры: важна форма картины. По той же причине GPU здесь исполняет пакеты по
одному в порядке отправки. Спецификация этого не обещает: порядок отправки — логический порядок, на который
опираются барьеры и семафоры, и сам по себе он не упорядочивает ни начало, ни конец работы (дальше — в
интерактиве [Очереди, семафоры и fence](lab:queue-sync)).

Что попробовать:

- пройти шагами один кадр с 1 кадром в полёте и посмотреть на дорожку CPU: после отправки он только ждёт;
- в тот же момент переключиться на 2 кадра в полёте и сравнить общее время и загрузку GPU;
- найти первое ожидание при 2 кадрах в полёте, которое действительно блокирует CPU, и кадр, которого он ждёт;
- следить за дорожкой очереди: между отправкой и стартом на GPU работа только *стоит в очереди*.
