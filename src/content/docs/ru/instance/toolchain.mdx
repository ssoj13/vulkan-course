Пора ставить софт. Вопрос урока простой: что нужно положить на машину, чтобы Vulkan-программа собиралась и
запускалась, и что из этого понадобится только вам, разработчику, а что — каждому, кто запустит вашу программу. К концу

## Место в курсе

Модуль «Основы» был про устройство мира: что такое [GPU](lesson:gpu), как до него доходит работа
([драйвер, command buffer, очереди](lesson:talking-to-gpu)), зачем Vulkan сделан явным и
[из каких объектов он состоит](lesson:object-map). Теперь начинается практика, и начинается она с рабочего
места. Этот урок почти не касается кода, зато после него всё остальное можно запускать руками. Из четырёх слоёв курса
урок касается слоя загрузчика и драйвера: runtime Vulkan — это загрузчик и драйвер, а SDK лежит рядом с ними и в
дерево объектов не входит.

Цепочка, по которой идёт любой наш вызов, и место инструментов в ней:

`наша программа → биндинг (ash / Vulkan-Hpp) → загрузчик vulkan-1.dll → драйвер GPU → GPU`

[ash](term:ash) и [Vulkan-Hpp](term:vulkan-hpp) построены на [загрузчике](term:loader): это лишь удобные обёртки над
его C-функциями. [Vulkan SDK](term:vulkan-sdk) в эту цепочку не встраивается — он лежит рядом и снабжает её
заголовками, [слоем валидации](term:validation-layer) и инструментами.

## Runtime и SDK: кто запускает, а кто помогает писать

Здесь легко спутать две вещи, хотя обе называются «Vulkan».

- **Runtime Vulkan** — это **загрузчик** (`vulkan-1.dll` на Windows) и сам драйвер. На Windows оба приходят вместе с
  драйвером видеокарты; в Linux загрузчик — отдельный пакет дистрибутива (`libvulkan1`, `vulkan-loader`), который
  ставится рядом с драйвером. Runtime нужен каждому пользователю вашей программы — и на Windows он у него уже есть,
  если драйвер свежий.
- **Vulkan SDK** (от LunarG) — это набор разработчика: заголовки, **слои валидации**, компиляторы шейдеров (`slangc`,
  `glslc`, `dxc`) и утилиты. Пользователям вашей программы он не нужен.

| Что | Откуда берётся | Кому нужно |
| --- | --- | --- |
| загрузчик `vulkan-1.dll` и драйвер | на Windows — драйвер GPU; в Linux — пакеты дистрибутива | всем, кто запускает программу |
| заголовки, `vulkan-1.lib` | Vulkan SDK | тому, кто собирает C/C++ |
| слой валидации, `vkconfig`, `vulkaninfo` | Vulkan SDK | тому, кто отлаживает |
| компиляторы шейдеров | Vulkan SDK | тому, кто собирает шейдеры |

<Aside type="tip" title="Аналогия из CG">
Это как Maya и Maya devkit. Художнику, который пользуется вашим плагином, нужна только сама Maya. Вам, автору
плагина, нужен ещё devkit: заголовки, библиотеки, примеры. Драйвер с загрузчиком — это «Maya», SDK — «devkit».
</Aside>

## Установка

<Steps>

1. Обновите драйвер видеокарты.

2. Поставьте Vulkan SDK с [vulkan.lunarg.com](https://vulkan.lunarg.com). Курс собирался на SDK **1.4.341.1**.
   Установщик заводит переменную окружения `VULKAN_SDK`.

3. Проверьте, что Vulkan жив: запустите `vulkaninfoSDK` (из папки `Bin` внутри SDK) с ключом `--summary`. Он
   перечислит ваши GPU и версию Vulkan, которую поддерживает каждый.

4. Откройте **Vulkan Configurator** (`vkconfig-gui` или `vkconfig gui` из терминала). Он умеет включать слои
   валидации для любой Vulkan-программы, не меняя её код. Он пригодится нам в [уроке о валидации](lesson:validation).

</Steps>

## Программы-примеры

Каждый шаг урока — маленькая законченная программа на двух языках. Файлы повторяют всё из предыдущих шагов, так что
один файл всегда показывает целую рабочую программу, без «см. выше».

<Tabs syncKey="code-lang">
<TabItem label="Rust (ash)">

[`ash`](https://crates.io/crates/ash) — тонкий биндинг для Rust: каждая функция и структура Vulkan отображается один в
один, а для структур есть builder-методы. `vulkan-1.dll` он открывает во время работы программы, поэтому для сборки
SDK не нужен вовсе.

```sh
cd examples/rust
cargo run --bin 01_instance
```

</TabItem>
<TabItem label="C++ (Vulkan-Hpp)">

[Vulkan-Hpp](https://github.com/KhronosGroup/Vulkan-Hpp) — официальные C++-биндинги от Khronos, они входят в SDK. Мы
пользуемся их слоем **RAII** (`vk::raii::*`): объект уничтожает себя сам, когда выходит из области видимости.
Официальный учебник Khronos написан в том же стиле. CMake находит заголовки и `vulkan-1.lib` через `VULKAN_SDK`, так
что здесь SDK нужен уже для сборки.

```sh
cd examples/cpp
cmake --preset msvc-debug
cmake --build --preset msvc-debug
.\build\msvc-debug\01_instance.exe
```

Команды нужно запускать из оболочки, где доступен компилятор MSVC `cl.exe` (Developer PowerShell).

</TabItem>
</Tabs>

Программа напечатает версию вашего загрузчика, список примерно из двадцати расширений instance и строку
`VkInstance created`. Что означает каждая из этих строк, разберём в [следующем уроке](lesson:loader-and-instance).

<Aside type="note" title="Почему именно Vulkan 1.4">
Обе программы просят Vulkan **1.4** — текущую версию (официальный учебник Khronos тоже на ней). Две возможности, на
которые мы опираемся везде, входят в ядро ещё с 1.3: *dynamic rendering* (рисование без объектов render pass) и
*synchronization2* (более понятные барьеры). 1.4 добавляет в ядро ещё кое-что, например push descriptors и улучшения
maintenance5/6. Последний релиз `ash` на crates.io (0.38, 2024 год) заканчивается на Vulkan 1.3, поэтому примеры на
Rust берут `ash` прямо из репозитория на GitHub, закреплённый на одном коммите, с поддержкой Vulkan 1.4. Когда выйдет
следующий релиз, перейдём на него.
</Aside>

## Что под капотом

- На Windows загрузчик ставится вместе с драйвером в системную папку (`C:\Windows\System32\vulkan-1.dll`), поэтому программа
  находит его на любой машине с актуальным драйвером, без всякого SDK.
- Слой валидации — это обычная DLL с JSON-манифестом рядом (`VkLayer_khronos_validation.dll` и
  `VkLayer_khronos_validation.json` в папке `Bin` SDK). Загрузчик находит слои именно по манифестам — об этом
  [следующий урок](lesson:loader-and-instance).
- Rust-программа и C++-программа доходят до одного и того же загрузчика: `ash` загружает DLL сам во время работы, а
  C++-сборка линкуется с import-библиотекой `vulkan-1.lib` из SDK.
